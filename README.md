# 纸桥 Paperbridge · EPUB 转 PDF

无需安装的本地 EPUB 转 PDF 工具。打开网页、选择 EPUB，在浏览器打印窗口选择“另存为 PDF”。

**在线使用：<https://aurigacapella.github.io/epub-to-pdf/>**

## 使用

1. 首次联网打开页面，等待右上角“离线已就绪”。
2. 拖入或选择一本 `.epub`，也可以点击“试试示例书籍”。
3. 设置 A4 / A5 / Letter、页边距、字体、字号、行距和章节分页；可选择需要导出的章节。
4. 点击“另存为 PDF”，应用会打开独立打印页；保持工作台打开，在打印窗口将目标打印机选择 浏览器内置的 **另存为 PDF / Save as PDF**，不要选择 **Microsoft Print to PDF**。
5. 使用默认缩放（100%），关闭浏览器页眉页脚。如需打印背景可自行开启背景图形。

推荐桌面版 Chrome 或 Edge。PDF 的分页以打印窗口为准；工作台显示连续排版预览。PDF 文字可选择、检索，非整页截图。

## 隐私与离线

- EPUB 在当前浏览器的 Worker 和内存中解压、读取与渲染，应用不会上传书籍，也不会把书籍写入 IndexedDB、localStorage 或 Cache Storage。
- 关闭、刷新或移除书籍会清除应用中的书籍状态。浏览器自身的打印记录、下载文件与崩溃恢复由浏览器管理。
- 所有运行依赖随网页一起提供，没有 CDN、第三方字体、统计或后端服务。
- 首次联网后缓存应用文件，之后同一浏览器、同一站点可断网打开；浏览器清除站点数据后需要重新联网。首次访问无法凭空离线加载。
- 浏览器生成 PDF 后请自行保存；应用无法确认用户是否保存或取消打印。独立打印页只通过同源窗口消息接收书籍，未使用本地持久化存储。若打印窗口未自动打开，点击打印页中的“打印 / 保存 PDF”。

## 0 字节 PDF 或打印任务留在队列

请在浏览器标准打印窗口中选择内置的 **另存为 PDF / Save as PDF**。它与 Windows 的 **Microsoft Print to PDF** 是不同的输出路径。用户反馈：约 71.8 MB 的 EPUB 使用后者生成 0 字节文件且任务滞留队列，切换浏览器内置保存后文件可正常打开。此反馈验证了替代输出路径，未确定系统驱动内部原因。

保存完成前保持工作台与打印页打开。应用无法从网页中检测系统打印队列，也不能确认文件保存成功。遇到大书排版过慢时，可在工作台选择部分章节后导出。

## 兼容范围

支持 EPUB 2/3 常见的可重排 XHTML 章节、spine 阅读顺序、本地图片（PNG/JPEG/GIF/WebP/AVIF/SVG）、表格、基础 SVG 与 MathML、ruby 注音和内部链接。中文字体使用系统字体。

为了稳定、私密地重新排版，原书 CSS、内联样式、嵌入字体、脚本、表单、音视频和外部资源不会保留。复杂竖排、固定版式和特殊公式不保证还原；固定版式会显示提示。存在加密资源或混淆字体的 EPUB 会明确拒绝，不进行 DRM 移除。

限制：单文件 100 MB、单个解压条目 50 MB、总解压 300 MB、最多 10000 个条目；解压超时 45 秒。大书受设备内存和浏览器打印能力限制。

## 本地开发

需要 Node.js 22 或更高版本。

```sh
npm ci
npm test
npm start
```

打开终端输出的 `http://127.0.0.1:4173`。部署文件位于仓库根目录，无需构建。通过 `file://` 直接打开不支持模块、Worker 和离线缓存，请使用 HTTP 服务或 GitHub Pages。

## GitHub Pages 部署

仓库 Settings → Pages → Deploy from a branch → `main` / `(root)` → Save。仓库包含 `.nojekyll`。所有资源使用相对路径，支持项目站点的子目录。

更改应用资源后同步更新 `sw.js` 中的缓存版本。新版本首次加载时可能仍使用旧缓存；关闭其他标签页并刷新后生效。

## 验证

`npm test` 覆盖 EPUB 2/3 元数据与阅读顺序、路径处理、压缩体积限制、损坏/缺失章节、加密资源、资源清理、内部链接、中文和打印样式。浏览器验收项目记录在 `docs/verification.md`。
